# Slot 2: Deploy and Inspect the Operator

> **Goal:** Set up the environment, install the CloudNativePG operator on the
> sandbox cluster, and explore the infrastructure.

## Set up the cnpg-playground

Clone the playground repository and run the setup script:

```bash
git clone https://github.com/cloudnative-pg/cnpg-playground.git
cd cnpg-playground
./scripts/setup.sh
```

Once it completes, verify the clusters are running:

```bash
./scripts/info.sh
```

## Set up the environment

Export the kubeconfig generated by the playground and switch to the EU
cluster context:

```bash
export KUBECONFIG=$(pwd)/k8s/kube-config.yaml

kubectl config use-context kind-k8s-eu
```

## Explore the playground infrastructure

The cnpg-playground has created a Kind cluster with six nodes.
Let's see them:

```bash
kubectl get nodes -o wide
```

Notice that three worker nodes carry the **postgres** role with a
**NoSchedule** taint, only workloads with the matching toleration will be
scheduled there:

```bash
kubectl describe node k8s-eu-worker3 | grep -A3 Taints
```

You should see:

```
Taints:  node-role.kubernetes.io/postgres:NoSchedule
```

This separation mimics a production setup where database pods run on
dedicated nodes.

## Install the cnpg kubectl plugin

```bash
curl -sSfL \
  https://github.com/cloudnative-pg/cloudnative-pg/raw/main/hack/install-cnpg-plugin.sh | \
  sudo sh -s -- -b /usr/local/bin
```

## Install the CNPG operator

Use the plugin to generate the operator manifests and apply them:

```bash
kubectl cnpg install generate --control-plane \
  | kubectl apply -f - --server-side
```

## Watch the operator come up

In a **separate terminal**, watch the pods:

```bash
kubectl get pods -n cnpg-system -w
```

Wait until the controller manager pod is `Running` and `1/1` ready.

## Install cert-manager and the Barman Cloud Plugin

CNPG uses the **Barman Cloud Plugin** for backup and recovery to object
storage. The plugin requires **cert-manager** for TLS certificate management.

Install cert-manager:

```bash
kubectl apply -f \
  https://github.com/cert-manager/cert-manager/releases/latest/download/cert-manager.yaml

kubectl rollout status deployment -n cert-manager cert-manager
kubectl rollout status deployment -n cert-manager cert-manager-webhook
```

Install the Barman Cloud Plugin:

```bash
kubectl apply -f \
  https://github.com/cloudnative-pg/plugin-barman-cloud/releases/latest/download/manifest.yaml

kubectl rollout status deployment -n cnpg-system barman-cloud
```

## Explore the CRDs

The operator has registered several Custom Resource Definitions:

```bash
kubectl get crds | grep cnpg
```

You should see CRDs such as `clusters.postgresql.cnpg.io`,
`backups.postgresql.cnpg.io`, `scheduledbackups.postgresql.cnpg.io`, and
others.

Inspect the Cluster CRD:

```bash
kubectl explain cluster.spec | head -40
```
